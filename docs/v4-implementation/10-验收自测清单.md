## 2. 对比度

### 2.1 静态对比度 `check-contrast.mjs`

Playwright 打开全部页面（§5 页面表），1440×900 与 390×844 两种视口，滚动到底再回顶（触发揭示），然后：

1. 遍历所有可见文本节点的父元素，读取计算后的 `color`。
2. 截取该元素外接矩形的屏幕像素，取像素亮度的中位数作为背景色（能处理光场、玻璃、渐变背景）。
3. 字号 ≥ 24px 或 ≥ 18.66px 且字重 ≥ 700 的为大字，阈值 3:1；其余 4.5:1。
4. 非文字元素：输入框边框、焦点环、选中指示条与相邻背景 ≥ 3:1。

输出不达标的页面、选择器、文字前 20 个字符、实测比值。

### 2.2 首屏逐帧对比度 `check-frame-contrast.mjs`

- 1440×900 打开 `/`、`/en`、`/technology`、`/en/technology`，从导航完成开始每 200ms 截一帧，共 50 帧（10 秒）。
- 对 H1、导语、两个按钮的文字区域，每帧计算文字颜色与背景像素中位数的对比度。
- **任何一帧** < 4.5:1 即不通过。

## 4. 中文标题断词 `check-zh-breaks.mjs`

Playwright 在 1440、1024、390 三个宽度打开全部中文页面，对每个 `h1`、`h2`：

1. 用 `Range.getClientRects()` 逐字取位置，找出每一行的起止字符。
2. 用 `content/v4/zh-breaks.json` 中该标题的词组边界作为“允许断点”；没有登记的标题，允许断点为标点之后与空格处。
3. 任何一行的断点不在允许断点上 → 报告（页面、宽度、标题、实际断开位置）。
4. 任何一行只有 1 个字或只有“AI。”这类 ≤ 3 字符的尾行 → 报告。

## 6. 录屏与帧差

### 6.1 录屏方法

- 使用**有界面的 Chrome**（不是无头模式），硬件加速开启，窗口内容区 1440×900；手机用 DevTools 设备模拟 390×844。
- 用 Playwright `recordVideo`（`size:{width:1440,height:900}`）或 Chrome DevTools 的屏幕录制，帧率 ≥ 30fps，格式 `.webm` 或 `.mp4`。
- 每段录屏开头 1 秒静止画面，文件名写清内容，例如 `S1-home-zh-1440.webm`。
- 每个交互再录一段减弱动效版本（DevTools → Rendering → Emulate CSS media feature `prefers-reduced-motion: reduce`），文件名加 `-reduced`。

### 6.3 帧差脚本 `scripts/frame-diff.mjs`

输入两张帧（或录屏中两个时间点抽帧，用 `ffmpeg -ss <t> -frames:v 1`；若环境没有 ffmpeg，改用 Playwright 在对应时间点截图），在指定区域内计算像素差：每个像素 RGB 欧氏距离 > 12 计为变化，输出变化像素占比。首页首屏的“舞台周围区域”为舞台外接矩形外扩 120px 的环形区域。

## 7. 性能（`scripts/measure-perf.mjs`）

### 7.1 方法

- Playwright + CDP，Chrome 稳定版。
- 手机：390×844、`deviceScaleFactor:3`、CPU 4 倍降速（`Emulation.setCPUThrottlingRate`）、网络 Slow 4G（下行 1.6Mbps、上行 750Kbps、RTT 150ms）。
- 桌面：1440×900，不降速。
- 每个页面冷启动（新上下文、禁用缓存）测 5 次，取中位数。
- TBT：从 FCP 到“load 后 5 秒”（手机）或“load 后 3 秒”（桌面），所有长任务（> 50ms）超出 50ms 部分之和（通过 `PerformanceObserver({type:'longtask'})` 注入页面采集）。
- LCP：`PerformanceObserver({type:'largest-contentful-paint'})` 最后一个值，并记录 LCP 元素选择器。
- 首屏字体：`performance.getEntriesByType('resource')` 中 `initiatorType==='css'` 且 URL 以 `.woff2` 结尾、在 LCP 之前开始请求的文件，`transferSize` 之和（同时记录 `encodedBodySize`）。
- 首页 JS：`production-budgets.mjs` 的 gzip 统计。

### 7.2 阈值

| 指标 | 页面 | 阈值 |
|---|---|---|
| TBT（手机） | `/`、`/en`、`/technology`、`/cases/proposal-generation` | ≤ 200ms |
| LCP（手机） | 同上 | ≤ 2.5s |
| LCP 元素 | `/`、`/en` | 首屏 `h1` |
| CLS | 全部页面 | ≤ 0.05 |
| 首屏字体 | `/`、`/about`、`/technology`（中文） | ≤ 150KB |
| 首页初始 JS（gzip） | `/`、`/en` | ≤ 180KB |
| `light-field.js`（gzip） | — | ≤ 8KB |
| 光场帧耗时（桌面真实 GPU） | `/` 首屏 | 单帧 GPU 时间中位数 ≤ 4ms（DevTools Performance 面板 GPU 轨道） |
