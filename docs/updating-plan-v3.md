## 2. 为什么 v2 显得塑料、粗糙、VI 不清

| # | 根因 | 表现 |
|---|---|---|
| 1 | **质感交给了生成图，界面本身没有材质。** 大厂官网的质感来自界面表面：有色相的底色层级、统一的光源、描边与内高光、可见但克制的阴影、颗粒、动效。v2 把这些都省了，改用 18 张 AI 生成的玻璃管、彩虹带、玻璃方块“贴”在纯黑纯白上 | 白底图露底板；图与内容无关；同一张图一页出现 5 次；“通用 AI 素材”观感 |
| 2 | **颜色来自生成图，不来自品牌。** v2 最后一次提交把 v1 的青绿单色族换成“青、钴蓝、琥珀、紫罗兰”四色光谱，图里又带进品红、粉、橙。语义色（玫红、琥珀、靛、绿）被当装饰用 | 遮住 Logo 认不出是同一家公司；VI 说不清 |
| 3 | **表面没有层级。** 深色只有纯黑，浅色只有 `#FFFFFF` 与 `#F6FAFC`（亮度差约 2%）；`#000` 与 `#FFF` 直接硬切 | “线框稿”“文档”感；滚动时明暗闪烁 |
| 4 | **细节没收尾。** 中文套等宽字回落宋体；SVG 刻度写死 `monospace` 落到衬线；圆点不在曲线上；失活缩略图叠白像坏图；页头灰带；英文方案页 H1 首词丢失 | 懂行的人一眼看出“没做完”，在证明工程能力的位置反向扣分 |
| 5 | **动效几乎没有。** 首屏只有一个计数切换，工作流不点亮，没有页面过渡 | “没有技术含量” |
| 6 | **篇幅翻倍，信息被摊薄。** 首页桌面从 7834px 涨到 11869px（约 13 屏），手机从 13 屏涨到 23 屏；大量 12–13px 等宽小字 | 买方：“Below that it is small monospaced labels… I skipped” |

v1 的质感为什么反而好：它只有一个色族（深青 `#062F3A`、`#3FA0A6`、薄荷 `#7EF5D6`），深色区带青色相，元素少。**质感 = 统一 + 有色相的表面 + 克制。** v3 要把这三点找回来，同时保住 v2 的大厂骨架。

## 3. 关于你提出的设想

你提了四个方向：UI 动态主题、毛玻璃、渐变光谱扩散、更有条理的明暗系统。判断如下。

| 设想 | 判断 | 理由与做法 |
|---|---|---|
| 动态主题 | **对，但要定义成“品牌光场”，不是主题切换。** | 一束用代码实时演算的、只用品牌青一族颜色的流动光，作为全站的核心视觉资产，在首屏、技术页、收尾三处以不同强度出现。它同时满足三件事：替代生成图成为品牌记忆点；是“实时演算动画”，直接展示开发能力；同一套代码改参数就能在不同页面复用，保证 VI 统一。细则见 §4.4 |
| 毛玻璃 | **对，但只能用在光场上方。** | 毛玻璃的质感来自“后面有东西被模糊”。放在纯白或纯黑上，模糊的是一片平色，只显得发灰。v3 只在光场上方的五类元素用：吸顶页头、首屏产品舞台的外框、下拉菜单与弹层、技术页架构面板、收尾 CTA 卡。内容卡片一律不用。细则见 §4.3 |
| 渐变光谱扩散 | **“扩散的光”要，“光谱”不要。** | 现在的塑料感有一部分恰恰来自彩虹、全息、品红色散。扩散光只在青一族内变化明度和饱和度，最多掺一点冷蓝做纵深；琥珀只表示“人工复核”，不做装饰 |
| 明暗系统 | **对，这是最该先做的。** | 明暗要有固定的角色和出现规律：暗是“舞台”（叙事与证据），亮是“纸面”（阅读与比较）；各有四级表面；过渡有固定做法。细则见 §4.5 |

你没提、但对质感影响更大的四件事，v3 一并加入：

1. **颗粒。** 深色渐变上加 2–3% 的噪点，消除色带，给表面“实物感”。v2 全站 0 处。
2. **统一光源。** 全站假定一个左上方光源，所有内高光、描边渐变、阴影方向都按它来。
3. **会被照亮的边。** 卡片顶部 1px 内高光，描边在鼠标靠近时被“照亮”（光斑跟随指针）。
4. **精度。** 等宽数字、像素对齐、图表做工、字体不回落。这些决定了“粗糙”还是“精密”。

## 4. v3 视觉识别系统

### 4.1 一句话定义

> **Cyano 是一束在深色里流动的青色光，它把散乱的资料汇成三条通道，落到一张清晰的工程纸面上。**

拆成三根支柱，每个视觉决定都要能归到其中一根：

| 支柱 | 是什么 | 来源 |
|---|---|---|
| 光 | 品牌光场：深色背景里缓慢流动的青色光，代码实时演算 | Logo 的青色 |
| 通道 | 三条平行通道与沿通道移动的光点，用作溯源线、流程连线、分隔、进度 | Logo 右侧三条通道和离散液滴 |
| 纸面 | 冷灰的工程纸面、单色线稿图、可读的真实界面局部 | 工程交付、“有据可查” |

验收时，评审要能用这三句话描述出这套 VI；说不出来就是没做到。

### 4.2 颜色

只保留一个品牌色族、一个中性色族和两个语义色。所有值先作为起点，在材质样张（§9 第 1 步）里校准对比度后锁定。

| 角色 | 值（起点） | 用途 |
|---|---|---|
| 品牌青 · Logo 本色 | `#3898A8` | Logo、浅色底上的大面积品牌色 |
| 品牌青 · 亮 | `#38C8E0`（Logo 深色版） | 深色底上的强调、光场高光、选中态 |
| 品牌青 · 浅 | `#A5ECF5` | 深色底上的大号数字、光场最亮处 |
| 品牌青 · 文字色 | `#0B6F80` | 浅色底上的链接、小字强调（≥ 4.5:1） |
| 品牌青 · 深 | `#062F3A` | 深色面板的色相来源（v1 已有） |
| 冷蓝（只用于纵深） | `#2B5BD8`，占光场能量 ≤ 10% | 只出现在光场里，不出现在界面元素上 |
| 琥珀 · 人工复核 | 深色底 `#F2B544`、浅色底 `#A65A06` | 只表示“人工把关 / 需要注意” |
| 玫红 · 旧做法与风险 | 深色底 `#FB7185`、浅色底 `#BE123C` | 只在“前后对比”里表示旧做法 |

规则：

- 钴蓝、紫、靛、绿、粉、橙、黄全部退出界面。
- 图表多系列用青的明度阶梯加中性灰，不用色相区分。
- 四位创始人、四个流程步骤、四条方案都不再各配一种颜色。
- 组件里不允许出现十六进制颜色，全部引用 Token（v2 现有 71 种）。

|---|---|---|

| N1 | `#0B1117` | 分区、嵌入面板 |
| N2 | `#111A21` | 卡片 |
| N3 | `#18242D` | 悬停、浮层 |

**浅色纸面（冷灰，大面积不用纯白）**

| 层 | 值（起点） | 用途 |
|---|---|---|
| P0 | `#F3F6F7` | 浅色区页面底 |
| P1 | `#F8FAFA` | 交替分区 |
| P2 | `#FFFFFF` | 只给卡片、输入框、界面截图框，让“白”成为被抬起来的表面 |
| P3 | `#E8EEF0` | 凹槽、表头、代码块 |

**材质配方**（每种配方写成一个组件，页面上不手搓）

| 配方 | 用在哪 | 做法 |
|---|---|---|
| 舞台底 | 深色区 | N0 + 品牌光场（不同强度）+ 2–3% 颗粒 |
| 玻璃 | 光场上方的五类元素（§3） | 底色 N1 约 58% 透明；`backdrop-filter: blur(20px) saturate(150%)`；1px 描边 `rgba(255,255,255,.08)`；顶部 1px 内高光 `rgba(255,255,255,.08)`；外阴影 `0 30px 80px -30px rgba(0,0,0,.7)`。同屏最多 3 块；玻璃不叠玻璃；单块面积不超过视口一半 |
| 深色卡 | 深色区里的卡片 | N2 底；1px 描边 `rgba(180,220,235,.10)`；顶部内高光；不用外阴影；悬停时描边按指针位置被照亮 |
| 纸面卡 | 浅色区里的卡片 | P2 底放在 P0 上；1px 描边 `rgba(12,28,36,.08)`；两层阴影 `0 1px 2px rgba(12,28,36,.05), 0 8px 24px -12px rgba(12,28,36,.10)`；悬停时阴影加一档、描边转青 30%、上浮 2px |
| 工程纸 | 浅色区里的图解、界面截图背后 | P0 上 1px 圆点网格，24px 间距，`rgba(12,28,36,.06)`，四周渐隐；只放在图背后，不放在正文背后 |
| 界面框 | 所有真实截图 | 只有一种：P2 或 N2 外框，10px 内边距，外圆角 20、内圆角 10，左上角用等宽字写系统名；不用仿 macOS 红黄绿圆点 |

**圆角**只有三档：8（控件）、14（卡片）、24（大面板、截图框）。嵌套时内圆角 = 外圆角 − 内边距（v2 有内角比外角还圆的情况）。胶囊形只留给按钮和标签。

**按钮**只有一套：深色底上是近白青 `#E8FBFE` 实心配深色字；浅色底上是 N0 实心配白字；次按钮是 1px 描边。悬停只加 1px 青色外发光。禁止渐变按钮。

### 4.4 品牌光场（实时演算）

| 项目 | 规格 |
|---|---|
| 实现 | 原生 WebGL 片元着色器画一个全屏面：两到三层带域扭曲的噪声场，颜色映射到 N0 → 品牌青深 → 品牌青亮 → 品牌青浅，掺 ≤ 10% 冷蓝；颗粒在着色器里一起加。不引入 three.js |
| 构图 | 光的能量集中在右侧和右上；文字栏背后（左侧约 45%）亮度压到接近 N0，保证正文对比度。光里有三条更亮的流线，对应 Logo 的三条通道，在首屏汇入产品舞台 |
| 动态 | 缓慢漂移，一个完整变化周期 20–30 秒；指针移动带来 ±2% 的视差；滚动改变相位，光“跟着”读者向下流 |
| 复用 | 同一份着色器、不同参数：首屏 100% 强度；技术页首屏换成“三条通道汇聚”形态，约 70%；中段嵌入暗面板 10–15%；收尾 CTA 与页脚 20%，并与首屏同一色调收尾 |
| 性能 | 以 50% 分辨率渲染再放大（光本来就是虚的）；设备像素比按 1 计算；静止时 30fps，交互时 60fps；离开视口或标签页隐藏即停；着色器与启动代码 ≤ 8KB gzip，在首屏内容绘制完成后的空闲时间再加载 |
| 首屏与降级 | 首次绘制先显示一张同构图的静态海报（AVIF，≤ 40KB），它就是 LCP 元素；WebGL 接管时淡入；不支持 WebGL 或 `prefers-reduced-motion` 时只显示海报 |
| 验收 | 滚动与空闲时没有超过 50ms 的长任务；文字栏背后的亮度在任何一帧都保证正文 ≥ 4.5:1 |

### 4.5 明暗编排

**角色：** 暗 = 舞台，用于叙事与证据；亮 = 纸面，用于阅读与比较。

**规则：**

1. 营销页（首页、解决方案、案例列表、技术、合作方式、关于、联系）与详情页（案例、方案）的首屏都是暗舞台，光场强度按 §4.4。文章与法律页首屏用纸面。v2 的做法是首页暗、其余全白，这让内页失去品牌感，也让“首屏风格”在页与页之间断开。
2. 正文区一律纸面。
3. 首屏之后，每页最多再出现一段暗区，只用来放这一页“最能证明我们”的内容（首页的“四个工程问题”、技术页的上下文引擎、案例页的界面实录）。它以**嵌入面板**的形式出现：在纸面中以 24px 圆角整块出现，四周留出纸面边距，像一块屏幕放在桌上。不再用通栏纯黑段。
4. 收尾 CTA 与页脚合并成一个暗区，光场低强度延续。
5. **过渡：** 首屏底部 160px 从光场渐隐到 N1，再进入纸面时，纸面顶部 240px 有一道极淡的青色“光漏”（约 4%）。不允许暗与亮直接硬切。
6. 吸顶页头在暗区上是玻璃，在纸面上是磨砂纸（P0 约 72% 透明 + 16px 模糊 + 底部 1px 线）；首屏顶部时页头底色与首屏一致（修掉 v2 的 `#333` 灰带）。

**各页明暗谱（目标）：**

| 页面 | 自上而下 |
|---|---|
| 首页 | 暗舞台（光场 100%）→ 纸面：结果带 → 纸面：四类场景 → 纸面：精选案例 → 嵌入暗面板：四个工程问题 → 纸面：合作方式 → 纸面：团队与洞察 → 暗：收尾与页脚 |
| 解决方案、案例列表、合作方式、关于、联系 | 暗舞台（光场 40%）→ 纸面若干段 → 至多一块嵌入暗面板 → 暗：收尾与页脚 |
| 方法与技术 | 暗舞台（三通道汇聚，70%）→ 纸面：四层架构 → 嵌入暗面板：上下文引擎与曲线 → 纸面：指标与生态 → 暗：收尾与页脚 |
| 案例详情、方案详情 | 暗舞台（本案例的三个指标）→ 纸面：背景与前后对比 → 嵌入暗面板：界面实录 → 纸面：流程与里程碑 → 暗：收尾与页脚 |
| 文章、法律 | 纸面首屏 → 纸面正文 → 暗：收尾与页脚 |

### 4.6 图形母题：三通道溯源线

v2 计划里的“溯源线”保留，形式改为来自 Logo 的三条平行通道：

- 一条通道 = 1.25px 的线；被引用的内容 = 线上的一个光点；校验点 = 线上的空心圆；人工复核 = 琥珀色空心圆。

- 动起来的方式只有一种：线按 stroke-dashoffset 从左到右画出，光点沿线移动。

## 7. 工程

技术评审 R-TECH：代码结构 4、性能 4、可访问性 5、可维护性 3、健壮性 4，工程展示力 4（v1 为 2）。可访问性第一次过线，其余仍低于 5。

| 项目 | v2 自报 | 实测 | 预算 |

**对质感影响最大的一条：字重全部失效。** 中文、Inter、等宽三套子集在生成时被固定成单一字重（`scripts/subset-font.mjs:22,39,191`），但 `@font-face` 声明的是字重范围，浏览器既不切换也不合成粗体。实测 300–700 的笔画墨量完全相同；中文首页 1,242 个、英文首页 1,482 个本该加粗的字符都按常规字重显示。标题、强调、按钮的层级因此塌缩，这是“显得平、显得廉价”的直接原因之一。只有 Manrope（英文标题）是真正的可变字体。
