## 1. 总体结论

**v3 的正文确实恢复成了 v1 定稿，是逐字恢复，不是改写后的近似。** 页面正文（不含页面标题、description、装饰图文字和图片 alt）里，中英文都没有找到擅改或遗漏。三篇文章 `articles.json`、演示数据 `query-demo.json`、`availability.json`，以及 `site/content/v1/` 下的 `cases.json`、`copy.json`、`founders.json`，与 `b9dcf94` 逐字段相同。上一轮报告第 1 节的 20 条重点问题，19 条已解决，1 条部分解决（法律页正文已恢复，但隐私、条款两页的 description 仍是 v2 文案）。

实施方说“0 缺失”，在它自己的统计范围内属实。范围放宽以后，还有三类出入（详见 1.2 和第 2 节）：

1. **首页首屏与页头装饰图没有恢复**：v1 首屏标书图里的“2 天 → 15 分钟”对比和三步流程，以及 22 个内页页头示意图上的文字，都已不在页面上。英文首屏还换成了另一个案例（IT Wiki），与中文不对等，“4 处明确差异”里也没有写。
2. **元数据被改**：8 个栏目页和 6 个案例页的 `<title>` 换了；全站 description 从 v1 的统一一句换成逐页文案。其中隐私页中文 description 写了“加密存储”，v1 正文只说“加密传输”。
3. **新增展示内容**：技术页新增一张“示意”延迟曲线，v1 没有这张图；另有若干界面标签和无脚本提示。

没有发现严重问题。另有 2 条重要、5 条一般、10 条轻微，见第 2 节。

### 1.2 与实施方“46 页、3,292 个片段、0 缺失”的口径差异

`site/scripts/check-v1-content.mjs` 的做法有以下几点会让它看不到上面的出入：

- 把 `BusinessHeroVisual`、`CoreVisual` 模拟成空组件（第 18 行），所以首屏标书图和页头示意图的文字不在基线里，被删也查不出来。
- 只渲染页面组件和页脚，不含页头导航和跳转链接；不比较 `<title>`、description、alt、aria-label、placeholder。
- 只保留长度不少于 4 个字符的文本节点，“2 天”“10×”“6+”“01”这类短片段不在检查范围。
- 只看初始渲染。切换项、演示问答、表单成功和失败状态都不检查（本报告用源码字符串补查，结论是没有缺失）。
- 只检查“是否出现在页面某处”，不检查位置和新增，查不出错位、中英差异和新增说法。

所以，“0 缺失”准确的说法是：**正文文本节点 0 缺失**。不能据此说“全部内容找回”。
