# V7 交互与动效评审：Cyano 官网 v3 生产构建（G5 第 3 轮）

- 评审对象：`next start` 生产构建，http://127.0.0.1:3010（中文 `/`，英文 `/en`）
- 评审方式：只读。用命令行启动无头 Chrome（`--headless=new`，CDP 9413 端口），通过 Node 内置 WebSocket 发送真实的 `Input.dispatchMouseEvent / dispatchKeyEvent / dispatchTouchEvent`，用 `Page.captureScreenshot` 连拍或 `Page.startScreencast` 录帧；同时在页面内读取 computed style、`document.getAnimations()`、`IntersectionObserver` 状态和滚动日志。测完已关闭 Chrome 进程。
- 视口：桌面 1440×900；手机 390×844（`mobile:true` + 触控模拟）。
- 帧存档：`docs/reviews/G5-round3-motion/`，共 242 张 JPG、90 组。下文提到的帧文件都在这个目录里。
- 参考源码（只读）：`site/components/v3/*`、`site/app/styles/v3.css`、`v3-foundation.css`、`v3-tokens.css`。
- 测量脚本（临时）：`…/scratchpad/v7/{lib,inventory,motion,nav,nav2,checks}.mjs`，原始数据在同目录的 `inventory.json`、`motion-*.json`、`nav*.json`、`checks.json`。

## 0. 一句话结论

v3 的方向是克制的“深色玻璃 + 青色光场 + 浅色纸面”，品味不土，基础无障碍也做到了（焦点环、跳转链接、tablist 方向键、减弱动效）。但从交互上看，这个站基本是静态的：几乎所有切换都是瞬切，浮层没有进出场，首屏光场被玻璃面板挡住、肉眼很难察觉，最能讲清 Cyano 业务的三个位置（首屏来源栏、解决方案图示、工作流）都没有动。另外有一个严重的导航缺陷：**站内点主导航后，新页面会自动平滑滚到页脚**。看完全站，能记住的交互只有技术页的延迟滑块，和案例详情里的问答 Demo。

## 1. 七项评分（1–7）

| 维度 | 分数 | 理由 |
|---|---|---|
| 交互丰富度 | **3** | 首页约 30 个反应点，其他页 7–12 个。数量够，但类型单一：大多是颜色变化、2–4px 上浮，或卡片的滚动进入。业务内容（架构四层、工作流、记忆分层、合作对比、原则、流程）全是静态块。/services 四张方案卡和 /insights 卡片悬停无任何反应。 |
| 反馈质感 | **3** | 有统一的 `--ease: cubic-bezier(.2,.7,.2,1)`，但时长散落在 .12/.2/.24/.25/.36/.6s 之间，部分规则还是浏览器默认 `ease`，`v3-foundation.css` 与 `v3.css` 两套 hover 规则叠加（合作卡上浮 4px/.2s 来自旧规则，案例卡上浮 2px/.24s 来自新规则）。下拉、灯箱、截图放大、手机菜单、所有 tab、FAQ 都是 0ms 瞬切。按钮按下没有 `:active` 反馈（实测 `transform:none`）。主按钮悬停只加 1px 青色描边，120ms，几乎感觉不到。 |
| 动效品味 | **4** | 克制，没有炫技、弹跳或大位移，色彩控制好。WebGL 光场方向正确（低频噪声、三条青色光带、有颗粒），但位置被 Hero 玻璃面板挡住，又只在右上角，等于花了 GPU 却没给到“品牌时刻”。整体偏“安静但空”，缺少一个让人眼前一亮的点。 |
| 信息价值 | **3** | 亮点有两个：技术页的延迟滑块（Cyano Core 恒定约 181ms，完整历史随轮次涨到约 2,800ms），以及案例页的 IT 问答 Demo（打字回答 + 来源 §1）。但首页“解决方案”四个 tab 的右侧图示**完全相同**（`EngineeringDiagram` 忽略了 `variant` 参数）。首屏来源栏 01/02/03 永远停在 01，工作流四步是静态卡片。最能证明“有出处、经人工复核”的位置都没有用交互去讲。 |
| 流畅度 | **3** | 掉帧方面没有问题：空闲时主线程 3 秒内只有约 0.08s 任务，JS 堆 15.6MB，光场 30fps 节流、半分辨率渲染、离屏暂停。但存在**跳变级**问题：站内软导航后，新页面会平滑滚到页脚（/cases 落在 scrollY 2903，/technology 落在 3507）；从页面中部点导航，新页面先停在旧位置，再用约 800ms 倒卷回顶部。这是用户最常走的路径。 |
| 无障碍 | **4** | 有：可见焦点环（深色区 2px #38C8E0）、跳转链接、两个 tablist 都支持方向键/Home/End、`prefers-reduced-motion` 下关闭光场和计数且显示终值、手机菜单有焦点陷阱和 `inert`。问题：图廊灯箱关闭后焦点掉到 `<body>`；手机菜单底部的主 CTA 文字与背景对比度约 1.05:1，几乎看不见；表单只有浏览器原生气泡，没有 `aria-invalid` 和内联错误；解决方案 tab 是“焦点即选中”，键盘用户扫过时面板一直在切换。 |
| 记忆点 | **2** | 能记住的只有延迟滑块和问答 Demo 的打字效果，而且都藏在三级页面。首页没有能让人转述给同事的交互（比如“鼠标移到引用上，会连线到原始文档”）。 |

- “时长/缓动”取自实测的 computed `transition` 和帧序列。

## 3. 问题清单（26 条）

### 【严重】

**1. 站内导航后，新页面被自动滚到页脚或倒卷到顶部**
- 位置：所有使用 `next/link` 的主导航、案例卡、页脚链接。实测从 `/`、`/services` 点“案例”或“方法与技术”。
- 帧：`zh-pagenav2-fromtop-0000ms…1000ms.jpg`、`zh-pagenav-home-to-cases-0000ms…0900ms.jpg`、`zh-pagenav2-fromscrolled-0000ms…1000ms.jpg`
- 现象：
  - 从页面顶部点“案例”：新页面平滑滚到 scrollY 2903（页脚）；点“方法与技术”：滚到 3507。用户看到的第一屏是“聊聊你希望改进的工作流程”和页脚。
  - 从首页中部（scrollY 1800）点击：新页面先停在 1739，再用约 800ms 倒卷到 0。
- 根因（滚动日志 `nav2.json` 证实）：Next App Router 在段切换时对段的首个 DOM 节点调用 `scrollIntoView`，依次落在 `FOOTER.footer`、`SECTION.closing`、`MAIN#main`、`SCRIPT`（`PageShell` 先渲染 JSON-LD `<script>`，`Footer` 也在 page 段内）。叠加 `v3-foundation.css` 的 `html{scroll-behavior:smooth}`，每次跳转都变成可见的平滑滚动。
- 建议：
  - 去掉全局 `scroll-behavior:smooth`，只在锚点跳转时用 JS 平滑滚动；或改为 `html:focus-within{scroll-behavior:smooth}`。
  - 把 `StructuredData` 与 `Footer` 移到 layout（或放在 `<main>` 之后的非首节点），让段首节点就是 `<main>`。
  - 回归测试：每个主导航入口落地时 scrollY 必须为 0，且无动画。

**2. 手机菜单主 CTA 不可见**
- 位置：手机端 `.mobile-nav .button`
- 帧：`zh-m-menu-open-0060ms.jpg`、`zh-m-menu-cta-contrast.jpg`
- 现象：文字 rgb(11,17,23)，背景 rgb(7,11,15)，对比度约 1.05:1。手机上最重要的转化按钮看不见。
- 建议：用 `--brand-mint` 或 `--ice` 底配 `--n1` 字（与桌面头部 CTA 一致），对比度 ≥ 4.5:1。

**3. 首页“解决方案”四个 tab 的右侧图示完全相同**
- 位置：`/` 解决方案区（`SolutionExplorerClient` → `EngineeringDiagram variant={selected}`，但组件内部不使用 `variant`）
- 帧：`zh-home-solution-tab3-0000ms…0320ms.jpg`、`en-home-solution-explorer.jpg`
- 现象：切换 tab 时，占面板 40% 面积的图示毫无变化（实测四个 tab 的 innerHTML 一致），交互退化成“只换一句话”。洞察卡用的也是这张图。
- 建议：至少做 4 张差异化示意（见方案 S6），切换时做 220ms 交叉淡入 + 节点位移。

### 【重要】

**4. 首屏品牌光场“有算力、没存在感”**
- 位置：`/` Hero（`.light-field.field-hero`）
- 帧：`zh-home-hero-ambient-0000ms…10000ms.jpg`（11 帧）、`zh-home-hero-pointer-left/right.jpg`、`zh-home-load-*.jpg`
- 现象：光带集中在 uv(.88,.68) 附近，正好被 Hero 玻璃面板盖住，只在面板右上缘露出一缕青色。实测 1s 只有 1.6% 像素明显变化，5s 为 9.7%。指针视差 ±0.02，扫满全屏帧差也只有 2.98%。10 秒连拍里肉眼只能看到右上角微弱漂移，没有品牌感。
- 建议：把光带主轴移到标题与面板之间的对角线，让面板“浮在光上”（面板背后做 backdrop 折射）。把指针响应提到 ±0.06–0.08，并加 600ms 阻尼。加载时做一次 1.2s 的光带扫入作为品牌时刻（见 S1）。

- 位置：`/` 产品舞台 `.source-rail`
- 帧：`zh-home-hero-ambient-*.jpg`

**6. 所有浮层没有进出场动效**
- 位置：导航下拉、图廊灯箱、Hero 截图放大、手机菜单
- 帧：`zh-home-nav-dropdown-hover-0000…0400ms.jpg`、`zh-casedetail-lightbox-open-0000…0600ms.jpg`、`zh-casedetail-lightbox-close-*.jpg`、`zh-m-menu-open-*.jpg`、`zh-m-menu-close-*.jpg`、`zh-home-hero-screenzoom-open.jpg`
- 现象：computed `animation:none; transition:all 0s`，全部 0ms 出现和消失。灯箱是 `dynamic()` 加载，首帧 50–150ms 页面无变化，随后整屏瞬现，体感是卡了一下再闪出来。
- 建议：
  - 下拉：opacity + translateY(-4px→0) + scale(.98→1)，180ms 进、120ms 出，加 80ms 悬停意图延迟。
  - 灯箱：FLIP，从缩略图位置放大到全屏，320ms，背景模糊 0→8px。
  - 手机菜单：clip-path 从按钮处圆形展开，或整体淡入，菜单项错峰 30ms。
  - 预加载 Lightbox chunk（悬停主图时 `import()`）。

**7. 所有选择类组件都是瞬切，没有选中指示器**

- 建议：
  - tab 用一个共享的滑动指示块（`transform` 220ms ease-out），面板 160ms 交叉淡入 + 8px 位移。
  - FAQ 用 `interpolate-size: allow-keywords` 或 grid-rows 0fr→1fr，240ms；图标旋转 45°。

**8. 案例筛选的语义和反馈都不对**

**9. 图廊灯箱关闭后焦点丢失**

- 帧：`zh-casedetail-lightbox-close-0000…0150ms.jpg`

- 位置：`/insights/proposal-draft-in-15-minutes`
- 帧：`zh-article-toc-hover.jpg`、`zh-article-toc-jump-0000/0100/0300/0600ms.jpg`
- 现象：目录没有当前章节高亮（8 个链接颜色相同），没有阅读进度，目录悬停反馈很弱。
- 建议：用 IntersectionObserver 做 scroll-spy，左侧 2px 指示条滑动 220ms；顶部加 1px 青色阅读进度条。

**22. 首屏加载没有编排**
- 位置：`/` Hero
- 帧：`zh-home-load-0000ms / 0058ms / 0292ms / 0692ms / 0992ms / 1508ms / 2500ms.jpg`
- 现象：HTML 到达后，标题、按钮、玻璃面板一次性出现，唯一的入场是光场 canvas 的 .6s 淡入；面板 `translateY(10px)` 是静态偏移，不是动画。
- 建议：0–600ms 依次出现 eyebrow → 标题（逐行，60ms 错峰，translateY 12→0）→ 正文 → 按钮；面板 200ms 起从景深位置（scale .97、blur 6px）推近；总长 ≤ 900ms，不阻塞 LCP（标题文字不能设 opacity 0，改用 clip 或 transform）。

**23. 滚动揭示只覆盖卡片**
- 位置：全站
- 帧：`zh-home-scrollin-cases-0000…0800ms.jpg`、`zh-m-home-scrollin-cases-*.jpg`
- 现象：只有 10 类 `motion-card` 有 16px 淡入上移，并且只对加载时位于首屏以下的卡片生效；区块标题、图示、表格、流程没有任何节奏；3 张卡同时出现，没有错峰。
- 建议：统一 `[data-reveal]`，区块级 360ms，组内错峰 60ms，最多 4 级。

**24. 站内软导航没有页面过渡**
- 位置：全站
- 帧：`zh-pagenav2-casecard-to-detail-0000…1000ms.jpg`、`zh-pagenav2-back-*.jpg`、`zh-pagenav-language-switch-0000…0800ms.jpg`
- 现象：`@view-transition{navigation:auto}` 只对整页导航生效（实测语言切换是整页），App Router 的软导航没有任何过渡。案例卡 → 详情时，卡片截图与详情 Hero 没有空间连续性。
- 建议：用 React `<ViewTransition>` 或 `document.startViewTransition` 包住路由切换，案例卡截图与详情图廊共享 `view-transition-name`（S8），其他页面做 180ms 交叉淡入。

**25. 合作方式对比表没有比较交互**
- 位置：`/engagement` `.comparison-table`
- 帧：`zh-engagement-table-hover.jpg`、`zh-engagement-process-hover.jpg`
- 现象：3×3 对比表悬停时行列无高亮；三张合作卡与表格列之间没有联动。
- 建议：悬停卡片时高亮对应列；或直接做成配置器（S7）。

**26. 卡片中的界面截图太小，看不清**
- 位置：`/` 与 `/cases` 案例卡的 `.browser-frame`
- 帧：`zh-home-scrollin-cases-0240ms.jpg`、`zh-home-casecard-hover-0400ms.jpg`
- 现象：截图被压缩到约 345×135px，文字不可读，悬停也不放大，“看界面”的承诺落空。
- 建议：悬停时截图在框内做 1.06 倍缓推 + 向下平移 6%，展示局部细节（Ken Burns，600ms）；或换成预裁好的局部特写。

## 4. 与标杆的差距分析

| 维度 | 标杆的常见做法 | Cyano 现状 | 差距类型 |
|---|---|---|---|
| **首屏的品牌时刻** | **Linear**：Hero 下方产品截图带光照遮罩和逐元素入场，暗色背景上有一道可见的光边。**Stripe**：可交互的渐变网格（WebGL）是视觉主角。**Vercel**：网格 + 光束、地球或部署动画直接讲产品。**Apple**：滚动驱动的产品揭示。**Anthropic**：极简，但字体编排与插画有节奏的入场。 | 光场藏在面板背后，10 秒只有约 10% 像素在变；面板静态；没有加载编排。 | 反馈弱 + 缺少空间层次（光源与面板没有关系） |
| **演示型交互** | **Stripe**：嵌入式产品 UI 动画（Checkout、Billing 状态流转），每个区块都有一个讲业务的小动画。**Linear**：每个功能区都有真实 UI 的微型动态（issue 流转、cycle 推进）。**Vercel**：部署日志、边缘请求动画。 | 只有一个 IT 问答 Demo（藏在 2 个案例页），以及一个延迟滑块。解决方案图示相同，工作流和架构静态。 | **最大差距**：缺少讲清“资料 → 工作流 → 有出处、经人工复核的结果”的演示 |
| **状态切换** | **Linear / Vercel**：tab 都有共享指示器滑动（约 200ms，ease-out），内容交叉淡入。**Apple**：分段控件用弹簧。**Stripe**：下拉菜单是带箭头的玻璃卡，宽高 morph。 | 全部瞬切；下拉瞬现。 | 缓动缺失 + 时长为 0 |
| **悬停手感** | **Linear**：卡片描边渐亮 + 内部光斑，在深色底上明显。**Vercel**：边框色加深 + 背景 1–2% 提亮，150ms。**Stripe**：按钮箭头位移 + 背景变化，150ms。 | 1px 描边光斑在浅色卡上看不见；按钮反馈弱；约 45% 的可点击元素悬停无变化。 | 数量够但反馈弱，并且不一致 |
| **空间层次** | **Apple / Linear**：玻璃、景深、视差，前后层运动速度不同。**Stripe**：3D 倾斜卡片。 | 有 `backdrop-filter` 玻璃，但面板背后没有可折射的内容；没有视差；没有景深变化。 | 缺少空间层次 |
| **滚动叙事** | **Apple**：粘性场景 + 滚动进度驱动。**Linear**：区块入场错峰，标题逐行。**Stripe**：滚动触发图表描线。 | 只有卡片淡入；图表不描线、条形不填充。 | 数量少 |
| **页面切换** | **Vercel / Linear**：软导航即时，不改动滚动位置，部分元素共享过渡。 | 软导航会滚到页脚或倒卷，无过渡。 | 有缺陷（跳变） |
| **性能** | 标杆在手机上通常降级为静态渐变或视频。 | 帧率、主线程、内存都轻；但手机仍跑 WebGL，指针光斑是全局监听。 | 小问题 |
| **无障碍 / 减弱动效** | **Apple / Stripe**：减弱动效时保留状态变化（淡入替代位移）。 | 减弱动效处理正确（关光场、显示终值、取消过渡），但灯箱焦点丢失、手机 CTA 不可见、表单错误不可感知。 | 局部缺陷 |

**总结**：差距不在性能，而在三处。
1. **演示型交互几乎为零**：Cyano 卖的是“可追溯的 AI 工作流”，标杆的做法是让访客在 10 秒内亲手“看见”这条链路。
2. **状态反馈的时长与缓动缺位**：大量 0ms 切换让站点显得像原型。
3. **空间层次只停在材质层**：有玻璃，但没有光与玻璃的关系，也没有景深和视差。

## 5. 方案

### 5.1 动效 token（所有方案共用）

```css
:root{
  /* 时长 */
  --dur-press: 80ms;     /* 按下 */
  --dur-fast: 140ms;     /* 颜色、描边 */
  --dur-base: 220ms;     /* 悬停位移、tab 指示器、面板交叉淡入 */
  --dur-enter: 320ms;    /* 浮层进入、揭示 */
  --dur-scene: 600ms;    /* 区块揭示、描线 */
  --dur-story: 1200ms;   /* 演示段落 */
  --exit-ratio: .7;      /* 退出 = 进入 × 0.7 */

  /* 缓动 */
  --ease-out: cubic-bezier(.2,.7,.2,1);          /* 沿用现有 --ease */
  --ease-in-out: cubic-bezier(.65,0,.35,1);      /* 场景、描线 */
  --ease-exit: cubic-bezier(.4,0,1,1);           /* 退出 */
  --ease-spring: linear(0,.22 7%,.62 17%,.9 28%,1.02 40%,1.01 55%,1);  /* 指示器、FLIP */

  /* 位移与光 */
  --lift-1: -2px; --lift-2: -4px;
  --glow-cyan: 0 0 0 1px color-mix(in srgb,var(--cyan) 55%,transparent),
               0 8px 30px -10px color-mix(in srgb,var(--cyan) 45%,transparent);
}
@media (prefers-reduced-motion: reduce){
  :root{ --dur-base: 1ms; --dur-enter: 1ms; --dur-scene: 1ms; --dur-story: 1ms; }
  /* 保留颜色与透明度变化，去掉位移、缩放和持续动画 */
}
```

#### S1 首屏「资料 → 草稿 → 复核」溯源舞台（Provenance Stage）

- **位置**：`/` Hero 右侧，替换现在的产品舞台；`/en` 用 IT 知识库版本。
- **用户操作**：默认自动播放一轮（约 7s），之后停在终态；悬停或聚焦草稿中的引用角标 `[1][2][3]` 时，可以反复触发溯源；点击来源栏的 01/02/03 跳到对应段落。
- **画面变化**：
  - **构图**：玻璃面板分三层景深。
    - 后层（z=-60px，blur 2px，opacity .7）：3 张斜向堆叠的“企业资料卡”（PDF 招标文件 / Excel 测算表 / Wiki 页面），显示真实的脱敏标题。
    - 中层：Cyano Core 节点（小圆环）。
    - 前层：生成中的方案草稿。
  - **0–1.2s**：资料卡依次从右后方滑入（translateZ + translateX），落位时边缘泛起一道青色描边光。
  - **1.2–3.6s**：从每张资料卡伸出一条溯源线（SVG path，stroke-dashoffset 描绘），线上有 1 个光点沿路径流向 Core，再从 Core 流向草稿；草稿逐句出现（每句 opacity + 4px 上移，不是逐字打字），句尾长出引用角标。
  - **3.6–4.8s**：右侧来源栏 01→02→03 依次点亮，与段落同步。
  - **4.8–5.6s**：“人工复核”区出现审核人头像 + ✓ 描绘，状态从“草稿”变为“已复核”，同时“15 分钟 / 99%”指标从灰变青。
  - **交互态**：悬停角标 `[2]` 时，其余溯源线降到 15% 透明度，`[2]` 对应资料卡从后层推近到前层（blur 消失、scale 1.04），并高亮其中一行原文。
- **时长 / 缓动**：入场 `--ease-out`；描线 `--ease-in-out` 600ms；光点 900ms；悬停推近 320ms `--ease-spring`。
- **视觉手段**：磨砂玻璃、景深（blur + translateZ）、溯源线 + 光点、渐变描边、光场从面板背后透出（光带移到面板后方，面板变成“折射窗”）。
- **性能预算**：纯 SVG + CSS transform/opacity；JS ≤ 6KB（gzip）；只动 transform/opacity/stroke-dashoffset；光场在演示期间保持 30fps；面板外 0 次布局抖动；LCP 元素仍是 h1。
- **减弱动效替代**：直接显示终态（三张资料卡 + 已复核草稿 + 静态溯源线），悬停角标时只做高亮，不做位移。
- **难度**：**L**

#### S2 Cyano Core 四层剖面（Layer Explode）

- **位置**：`/technology` “Cyano Core” 区，替换现在的四张平铺卡。
- **用户操作**：滚动驱动（粘性 200vh）；或点击右侧层名直接跳到该层。
- **画面变化**：
  - **初始**：四块玻璃板等距叠放（rotateX 55°，rotateZ -30°），像一块芯片。
  - **滚动 0–25%**：板间距从 8px 拉开到 64px，最上层“知识摄入”点亮，一份 PDF 图标碎成 6 个片段落进第一层的索引格子。
  - **25–50%**：“上下文编排”层点亮，片段中只有 3 个被选中（青色），其余变暗，被装进一个标有“Token 预算”的框。
  - **50–75%**：“任务执行”层点亮，片段沿 SOP 步骤（3 个节点）流动。
  - **75–100%**：“权限与审计”层点亮，输出带上锁图标和日志条。
  - 左侧文案随层切换，交叉淡入。
- **时长 / 缓动**：滚动映射（`animation-timeline: view()`，带 Safari 回退）；层点亮 220ms；片段落下 `--ease-spring`。
- **视觉手段**：3D 透视、玻璃板叠层、渐变描边、粒子（≤ 24 个 DOM 节点或 1 个 canvas）、景深。
- **性能预算**：每帧只改 transform；粒子 ≤ 24；移动端退化为垂直排列 + 依次点亮，不做 3D。
- **减弱动效替代**：静态的展开态等距图，四层同时显示，每层旁边配文字说明。
- **难度**：**M/L**

#### S3 上下文装箱器（Context Window Packer）

- **位置**：`/technology` 延迟曲线上方或旁边，与 S4 共用一个“对话轮次”控制。
- **用户操作**：拖动轮次（1–100），或切换“完整历史 / Cyano Core”两种模式。
- **画面变化**：
  - 一个横向的“上下文窗口”容器（固定宽，表示 Token 上限），每一轮对话是一个色块（用户 / 助手 / 资料片段 / SOP 指令）。
  - **完整历史模式**：轮次增加时，色块不断塞入，容器满后溢出部分变红并抖动，中间的“关键指令”块（琥珀色）被挤到中段、变暗（对应“指令遗漏”）；成本读数上涨。
  - **Cyano Core 模式**：只有 3–5 个相关块被选入（青色描边），其余块变成小点排在容器外的“索引”里；关键指令始终钉在容器左端。
  - 切换模式时，色块用 FLIP 重排。
- **时长 / 缓动**：FLIP 320ms `--ease-spring`；读数 tween 240ms。
- **视觉手段**：色块 + FLIP、琥珀色警示、溢出抖动、青色描边选中。
- **性能预算**：≤ 120 个 DOM 块（超过 100 轮时合并显示），transform 动画；无 canvas。
- **减弱动效替代**：两种模式并排做静态对照图，拖动时只更新数字和块的颜色，不做位移。
- **难度**：**L**（需要与内容团队确定示意数据口径，并沿用“示意数据”声明）

## 6. 未能验证的部分

1. **真实 GPU 帧率**：无头 Chrome 用 SwiftShader 软件渲染（`ANGLE … SwiftShader driver`）。实测空闲 45fps、滚动时 rAF 87fps，最长单帧 100ms，这些数字不代表真实设备；光场在独显、集显和手机 GPU 上的表现需要真机录屏（DevTools Performance / Safari Timeline）。
2. **帧序列的时间戳精度**：`captureScreenshot` 连拍有 30–250ms 的抓帧延迟（例如下拉菜单标称 60ms 的帧，实际在 213ms 抓到）。文件名里的 ms 是计划时刻，实际时刻记录在 `motion-*.json` 的 `real` 字段。页面切换和加载改用 screencast，文件名就是实际时刻。0ms 瞬切的结论来自 computed style（`transition: all 0s`、`animation: none`），不依赖帧精度。
3. **其他浏览器**：没有测 Safari（`backdrop-filter`、`@view-transition`、`interpolate-size` 支持度不同）、Firefox 和真实的 iOS/Android 触控（只用了 CDP 的触控模拟，手势和惯性滚动没有真实验证）。
4. **读屏器**：没有用 NVDA/VoiceOver 实际朗读。`aria-live` 和 `role=status` 只确认了 DOM 存在。
5. **表单真实提交**：为避免向 `/api/contact` 发送真实咨询，没有提交有效数据。“提交中 / 成功 / 失败”三态只读了源码，没有截帧。
6. **问题 1 的触发范围**：在 `/`→`/cases`、`/`→`/technology`、`/services`→`/cases`、`/cases`→详情（详情落地为 0，正常）、`history.back()`（恢复到 605，正常）这些路径上验证过。其余路由组合可能因段结构不同而表现不同，修复后需要全路由回归。
7. **主观判断**：“品牌感”“记忆点”“品味”和标杆对照基于评审者经验，没有做用户测试。
8. **CLS / LCP**：没有测量动效改造前后的 Web Vitals。S1 和 S2 的性能预算是设计目标，不是实测值。
9. **英文其他页面与 `/privacy`、`/terms`、404**：没有逐一测试，推断与中文版共用组件，表现一致。
