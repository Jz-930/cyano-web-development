## 2. 根因：三个版本的摆动

| 版本 | 做法 | 结果 |
|---|---|---|
| v2 | 加了大量生成图、多色光谱、改写了文案 | 方向对，但塑料、VI 散、内容失控 |
| v3 | 把生成图全部撤掉，用克制的材质与线稿，恢复 v1 文案 | 干净、可信，但空：没有主视觉、没有点缀、没有交互、不击中 |
| v4 | **在 v3 的地基上加东西，不再推倒重来** | 目标见 §8 |

v3 的问题不是方向错，而是三件事只写进了计划、没有做出来：计划 §4.4 要求光场“构图集中在右侧、三条流线汇入产品舞台”，实际被舞台挡住；§4.6 要求三通道溯源线贯穿全站，实际只有一处 60px 短线；§4.9 要求首屏舞台轮播、溯源线画出、工作流点亮、页面过渡，实际都没有。v3 自报的验收也没有覆盖这些项。

所以 v4 的关键不是新想法，而是：**把“大美术、点缀、交互、表达”变成有清单、有样张、有验收的交付物。**

## 3. 主视觉与大美术

### 3.1 原则

视觉总监的判断：Cyano 卖的是“把散乱资料变成有据可查的工程产出”，所以**主角是高保真的产品样机加上被画出来的溯源过程**，光场负责气氛，三通道负责叙事，样机负责证据。不是抽象的光，也不是孤立的 3D 物体。

### 3.2 三种制作手段，各管各的

| 手段 | 用在哪 | 怎么做 | 质量门槛 |
|---|---|---|---|
| **A. 高保真产品样机**（主力） | 首页首屏、方案总览与详情首屏、案例封面与详情首屏、首页方案区、四个工程问题 | 用 HTML/CSS 重建真实界面的关键区域（文字是真文字，13–14px），分前中后三层叠放（后层来源卡模糊 2px、透明 70%；中层主界面窗；前层玻璃指标牌），三通道溯源线用 SVG 画出并能动。真实截图只用于“界面实录”和灯箱，且裁出焦点区按 ≥ 0.8 倍显示，源图至少 2 倍分辨率 | 截图里文字可读；1440 与 390 两个宽度都不发糊；每张样机对应一个真实案例，数字与案例一致 |
| **B. 实时品牌光场**（升级现有 WebGL） | 首屏、技术页首屏（三通道汇聚形态）、嵌入暗面板、收尾区 | 能量主轴移到标题与样机之间的对角线，样机浮在光上；三条亮流线汇入样机左缘；颗粒提到 2.5–3%；指针响应 ±0.06–0.08 并加阻尼；加载时 1.2 秒光带扫入一次作为品牌时刻；手机端改用烘焙了颗粒的静态海报加 CSS 平移 | 首屏 5 秒内肉眼能看到光在动；文字栏背后任何一帧正文对比度 ≥ 4.5:1；光场代码 ≤ 8KB gzip |
| **C. 静帧主视觉**（少量、锁定风格） | 收尾区背景、技术页首屏的补充、OG 分享图、洞察封面底图 | 只做一个系列：“三通道光学结构”（Logo 右侧三条通道与离散光点的立体化），单一青色族、纯深色背景、左上单一主光、无彩虹色散、无彩色珠子。先用 `lock-visual-style` 工作流锁定风格样张，再批量生产；每张过视觉总监的单图评分（原方案 §8.9）才能上线。v2 生成图的教训：不锁风格、不逐张评审，就会变成十几种语言 | 同一系列光源、饱和度、材质一致；同一张图一页最多出现一次；不露底板（透明通道或纯色底加遮罩渐隐） |

文章封面用代码生成的排版封面（视觉总监报告 §3-7）：底是 25% 强度的光场（每篇种子不同），左下是标题关键词，右侧是该文的核心工程图；首页、洞察列表、文章首屏、OG 图共用。

## 6. 表达与内容：学竞品，但不改事实

### 6.1 竞品为什么击中人

详见 `docs/reference-study.md`。一句话：**它的资料按“买方怎么做决定”的顺序组织**——市场这么乱我该选谁 → 我在怕什么 → 别家缺什么 → 你能做哪些具体的事、快多少 → 跟别的路线比怎么样 → 我还有这些顾虑 → 下一步怎么开始。它的视觉不高级，但表达到位；Cyano 视觉更好，但读者拿到的“为什么选你”更少。

要吸收的九种表达模式：用买方的问题开场；给顾虑起短名字并配答案；“≠”句式；按类别和替代方案逐项对比、自己一列高亮；一个贯穿全站的类比；场景卡写“之前 → 之后”时间对比；资历后接“也就是说”；FAQ 用买方的口吻提问（含“嫌贵”“不急”）；可照着走的落地路径。

不能照搬的：极限词（唯一、第一、最高等级）、保证性承诺（永远不出门、绝对安全）、点名竞争对手公司、客户名称墙、奖项资质墙、无依据的数字（“20 倍”“3–5 年领先窗口”）、它的订阅与一体机卖点。

### 6.3 改文案的规矩

你两次明确了态度：v3 要求“找回 v1 最后定稿的全部内容”，这次要求“充分吸取竞品的表达和形式”。两者并不冲突，做法是：

1. **事实与数字一律不动**，只用 v1 定稿、事实表和 `content/sources.md`。
2. **表达升级写成对照稿**：`content/copy-proposals-v4.md`，每一块三栏——v1 原文 / 建议稿 / 依据。你逐块批准，批准的才进 `site/content`。没批准的保持 v1。
3. **需要新事实的地方单列**，由你提供后再写（例如替代方案的成本与周期、培训内容、基准原始数据、更多场景的前后时间）。
4. 内容核对脚本复跑：页面上的每个数字必须在 `sources.md` 有登记；v1 定稿在未批准的块里必须原样。
