| 编号 | 文件 | 形式 |

| B | 《2026 微趣MyGPT 政企私有化AI开箱即用》 | 长页面，产品型落地页（约 10,860pt 高） |

本笔记记录它们为什么容易击中用户、Cyano 能吸收什么、不能照搬什么。用法是学它的表达方式和组织方式，不抄它的文字、图片、品牌元素（原方案 R3）。示范写法都用 Cyano 自己已有的事实。

---

## 1. 一句话结论

**它的力量不在视觉，在于整份资料是围着“客户怎么做购买决定”组织的。** 每一屏只回答买方心里的一个问题，问题按决策顺序排列：市场这么乱我该选谁 → 我到底在怕什么 → 别家缺什么 → 你有什么 → 能做哪些具体的事、快多少 → 跟别的路线比怎么样 → 我还有这些顾虑 → 下一步怎么开始。

Cyano 现在的组织方式是“我们是谁、我们做什么、我们怎么做”，是从卖方往外讲。内容准确，但读者要自己把它翻译成“这跟我有什么关系”。

它的视觉本身并不高级（emoji 图标、通用白卡片、标准蓝），Cyano 的视觉标准应高于它。要学的是信息组织和表达，不是外观。

## 2. 它为什么击中用户：九种表达模式

| # | 模式 | 它怎么做（引用不超过 15 字） | 为什么有效 | Cyano 现状 |
|---|---|---|---|---|
| 1 | **用买方的问题开场** | A 首屏是一个提问：“政企客户到底该选谁？”，下面一行小字写明“基于各厂商公开信息整理” | 读者第一眼看到的是自己正在纠结的事；小字让后面的比较显得客观 | 首屏是卖方陈述“为企业开发日常工作用得上的 AI”，准确但不制造代入感 |
| 2 | **给顾虑起短名字，每个顾虑配一个答案** | B 把顾虑压成四个三字词：不敢用、用不起、用不好、跟不上；每张卡下方一个绿色答案框 | 顾虑被命名后读者会对号入座；问答成对，扫一眼就完成“担心 → 放心” | 首页“四个工程问题”（资料分散、信息取舍、结果核查、团队使用）是工程视角的名字，买方不一定认出这是自己的顾虑 |
| 3 | **“≠”句式拆掉误解** | A 的“认知差异”：模型能力 ≠ 落地能力；部署交付 ≠ 产品交付；技术指标 ≠ 客户价值 | 一个符号把差异说清，读者不用读正文就知道立场 | 没有 |
| 4 | **跟替代方案逐项对比，自己那一列高亮** | A 九个维度对比五类方案（大厂云平台、开源模型、一体机、公网 AI、自己）；B 三种路线对比表；✓ ✗ 加短语 | 买方本来就在比，替他比完；按“类别”比而不是按公司比，读者能把自己的现状放进去 | 合作方式页有三种合作方式的对比，但没有和“买方的其他选择”对比（直接用通用聊天工具、买平台自己开发、找外包、买标准化产品） |
| 5 | **类比** | A“卖食材 vs 订餐到桌”；B 四层能力分别比作发动机、大脑、操作系统、即战力；数据安全比作自家保险柜 | 把技术概念换成生活经验，非技术决策者也能复述给老板 | 没有 |
| 6 | **场景卡写“之前 → 之后”** | B 十六张场景卡，每张有部门标签（HR、法务、财务）和时间对比条“2小时整理 → 5分钟” | 读者按部门找到自己，时间对比是可以直接拿去汇报的数字 | 案例有“2 天 → 15 分钟”等数字，但只集中在少数地方；方案页没有按部门、按任务的具体场景 |
| 7 | **把资历翻译成意义** | B 每条资历后接一句“也就是说，……”；A 每个优势下有一行灰字“行业现状：……”作对照 | 资历本身不说明价值，加一句翻译读者才知道“所以对我有什么好处” | 首页数字条“6+ 年 / 100% / 100% / 6 个行业”只有数字和标签，没有“也就是说” |
| 8 | **异议处理用客户原话提问** | B 的 FAQ：“免费的 DeepSeek 不就够用了吗？”“价格能不能再便宜点？”“AI 太新了，我们不急着上。” | 说出了客户不好意思问出口的话，回答显得坦诚；连“不急”和“嫌贵”都接住了 | 合作方式页 7 条 FAQ 是卖方提问的口吻（如“如何获得定制方案？”），没有接“直接用 ChatGPT 不行吗”“我们 IT 能自己搭”这类真实异议 |
| 9 | **给出可以照着走的落地路径** | C 最后一页：试点 → 拓展 → 全员推广，第一步写清从哪个部门、多大规模开始 | 降低“迈出第一步”的心理成本 | 有“低启动试点 2–6 周”和五步合作流程，但没有在首页或收尾处明确“第一步做什么、多大、多久” |

另外几条贯穿全篇的手法：

- **每屏一个结论，结论放在标题里。** 读者只看标题就能串起整个论证。
- **每屏末尾一句“金句”收束**（蓝色竖线引文块），例如对比表下方一句话总结。
- **关键短语加粗或变色**，正文扫读时只看加粗也能明白。
- **大数字三连**（B：100% / 0 / ∞ / 10+），用在信任与安全段。
- **重复少数几个核心承诺**（数据不出门、开箱即用、订阅），全篇反复出现，读完能记住。
- **短句、口语、第二人称“您”**。

## 3. 版式形式

| 形式 | 它怎么用 | Cyano 是否借鉴 |
|---|---|---|
| 首屏上方的胶囊标签（说明资料性质） | “行业深度对比 · 基于公开信息整理” | 借鉴：首屏眉题可以说明“这一页能帮你判断什么” |
| 每节标题下一条短蓝线 | 全篇统一 | 不借鉴，Cyano 已有自己的眉题系统 |
| 明暗交替，一段深色放“行业格局”这类观点段 | A、B 都是浅—深—浅 | 已有，v3 的明暗规则更完整 |
| 对比表：自己的列整列高亮、加表头色块 | A、B | 借鉴，做成 Cyano 的材质（玻璃或高亮描边列） |
| 场景网格：编号 + 部门标签 + 时间对比条 | B 十六张 | 借鉴结构，视觉按 Cyano 规范重做 |
| 顾虑卡：红色顾虑名 + 绿色答案框 | B | 借鉴结构，不用红绿配色（Cyano 用玫红表示旧做法、品牌青表示答案） |
| 输入 → AI → 输出 三栏图 | C“把资料丢给它，就像丢给同事” | 借鉴，并升级为首页的动态主视觉（见 v4 计划） |
| 公式图 A + B + C = D | C“大模型 + 应用 + 业务数据 = AI 生产力” | 可以借鉴到技术页 |
| emoji 图标、圆形发光图标 | 全篇 | 不借鉴，与 Cyano 的工程线稿语言冲突 |
| 客户名称胶囊墙 | B“他们已经在用” | 不能照搬（R9 不写客户名）；`content/inputs/clients.json` 有数据时可用 Logo 墙 |

## 4. 不能照搬的部分

| 它的做法 | 为什么不能用 | Cyano 的替代 |
|---|---|---|
| “唯一”“全国第一台”“最高等级”“最懂政企” | 原方案 §3.6 红线：《广告法》极限用语 | 用具体事实代替程度词：“6 年以上”“2 天 → 15 分钟” |
| “数据永远不出门”“数据绝对安全” | §3.6 红线：保证性承诺 | 写做法：“私有化部署时，模型与数据在你的环境中运行”（v1 已有） |
| 点名百度、阿里、华为、科大讯飞等公司并评价 | 点名评价竞争对手有法律与口碑风险，也不符合 Cyano 克制的语气 | 按“方案类别”比较：通用聊天工具、模型平台加自建团队、标准化 AI 产品、外包开发、Cyano |
| 列出国家安全局、公安部等客户名称 | R9：客户企业名称不写进网站 | 用“某企业 + 行业”加案例数字；客户授权后走 Logo 墙 |
| 奖项、标准、认证、实机参展 | §3.6 红线：不编造资质；Cyano 目前没有这类资质 | 用团队硬事实、真实系统截图、可试用的在线 Demo、交付流程与负责人建立信任 |
| “锁定 3–5 年领先窗口”“三年总成本是自建的 5–10 倍” | 无依据的预测与数字，违反 R5 | 只用 `content/sources.md` 已登记的数字；需要新数字时由负责人提供 |
| 订阅、硬件、标准化产品的卖点 | 业务不同：Cyano 是定制工程、低启动试点、托管服务 | 对应的卖点是“用你自己的资料”“先试点再扩展”“上线后有人维护”“不绑定某一个模型” |

## 5. Cyano 可以怎么吸收（方向，具体文案需负责人确认）

负责人此前要求正文以 v1 定稿为准。下面的改动会改变表达方式，所以 v4 的做法是：**事实与数字一律沿用 v1 和 `content/sources.md`，表达升级写成“v1 原文 / 建议稿”对照稿，逐块由负责人确认后再上线。** 不再出现 v2 那样“先改了再说”。

| 位置 | 吸收的模式 | 方向示例（只用已有事实） |
|---|---|---|
| 首页首屏 | 1 用买方问题开场 | 保留 v1 主标题，在其上方加一句买方问题作眉题，例如“通用 AI 很多，为什么还是用不进日常工作？”（备选，需确认） |
| 首页信任条 | 7 也就是说 | “6+ 年：每位核心成员的最低开发经验。也就是说，你的项目由资深工程师直接负责。”（后半句是新表述，需确认） |
| 首页“四个工程问题” | 2 顾虑命名 + 答案 | 在 v1 四个问题前加买方能认出的短名，例如“找不到 / 说不准 / 不敢用 / 用不开”，对应资料分散、信息取舍、结果核查、团队使用；每个配 v1 已有的 Cyano 做法作答案（短名需确认） |
| 首页新增一节“几种做法怎么选” | 4 类别对比表 + 5 类比 | 对比：直接用通用聊天工具 / 买模型平台自己开发 / 外包软件公司 / Cyano。维度取 v1 已有说法：是否用你自己的资料、回答是否有出处、权限、结果核查、上线周期、上线后谁维护、模型是否绑定。表下一句收束（需确认） |
| 首页新增“≠”三条 | 3 ≠ 句式 | 例如“能聊天 ≠ 能接进流程”“回答流畅 ≠ 有据可查”“上线 ≠ 有人维护”，每条下接 v1 已有的一句解释（需确认） |
| 方案详情页 | 6 场景卡 之前 → 之后 | 只用已登记数字：标书“2 天 → 15 分钟”、IT 知识库“80% 常见咨询自动处理，平均响应 < 3 秒”、数据查询“0 行 SQL，秒级出表”；其他场景若要写时间对比，需负责人提供数字 |

## 6. 视觉上的启示

- 它证明了一件事：**表达到位时，朴素的视觉也能打动人；反过来，精致的视觉也救不了没有组织好的信息。** Cyano v3 的视觉已比它高一档，但读者获得的“我为什么要选你”的信息比它少。v4 要两手都做。
- 它最有效的几个“图”都是信息结构图，不是装饰：输入 → AI → 输出、对比表、之前 → 之后时间条、公式。这些正是 Cyano 应该画成“大美术”的地方：用 Cyano 的光、玻璃、溯源线，把这些结构做成高质量、会动的主视觉，而不是继续用通用节点线稿。
